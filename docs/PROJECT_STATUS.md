## Phase 3 — Database & authentication ✅

**Implemented:** 8 models (users, resumes, resume_revisions, jobs, analyses, matches, recommendations, exports) with explicit constraint naming; UUIDv7 identifiers; Alembic migrations `0001_users` and `3902…` (autogenerated, then applied to PostgreSQL); registration, login, refresh, logout, `/auth/me`, account deletion; `get_current_user` dependency; bcrypt with SHA-256 pre-hashing; JWT access 15 min / refresh 14 days with `token_version` invalidation.

**Verified:** 8 tables present in PostgreSQL · `users` columns match the model · 14 auth tests pass, including identical 401 bodies for unknown email and wrong password (no account enumeration) and a test asserting `password_hash` never appears in any response.

**Known deviation:** `logout` bumps `token_version`, invalidating *all* refresh tokens for the account. `API.md` describes revoking only the presented token, which needs a refresh-token table; that is deferred rather than faked. Documented in the service docstring.

## Phase 4 — Document ingestion ✅

**Implemented:** size → extension → magic-byte → structural validation (a file whose bytes contradict its extension is rejected with `415`); PyMuPDF and python-docx extraction preserving page count and paragraph order; low-text PDFs reported as `partial` with warnings rather than silently returning thin text; content-addressed object storage (never in the database, path traversal rejected); 5 MiB limit enforced *while reading*, not after buffering.

**Verified:** 15 tests, fixtures generated at runtime (a checked-in binary cannot drift out of step with the code). Oversize → 413, disguised PNG → 415, empty → 422, low-text → `partial` + warning.

**Limitation:** OCR is specified but not implemented — no OCR dependency exists, so scanned documents are reported as `partial` and the user is told why. The product does not pretend to read them.

## Phase 5 — Resume intelligence ✅

**Implemented:** canonical section detection with variant headings; contact, experience, education, projects, certifications, achievements, leadership; date parsing across `Mar 2024`, `03/2024`, `2024`, `Present`, with `date_precision` and ambiguity flagged instead of guessed; bullet splitting with character spans; a skill taxonomy with aliases, longest-match-first; explicit skills separated from *inferred* ones, each with the basis that produced it.

**Verified:** 24 parser tests. The central assertion is negative: a value that cannot be determined stays `None` and appears in `uncertain`.

**Bug found and fixed in this pass:** institution names were truncated at the matched keyword, turning "National Institute of Technology" into "National Institute". Now resolved by delimiter boundaries. Phone extraction only handled 3–4 digit groups (`+91 98765 43210` silently dropped); the pattern now accepts a digit run and validates length.

## Phase 6 — Explainable scoring engine ✅

**Implemented:** all 27 criteria (CQ/EX/SK/ST/AT/LR), per-criterion applicability, weighted aggregation, ownership-uniqueness assertion, confidence derivation, band assignment, findings with verbatim evidence and `score_impact`, strengths, priority actions.

**Verified:** 13 scoring tests + 6 end-to-end API tests. Determinism, weight conservation, `applicable_weight == 80` for a resume with no experience, and `Σ score_impact == 100 − overall` within 0.1 are all asserted.

**Bug found and fixed in this pass:** confidence measured evidence density against a fixed expected count, so a *flawless* criterion producing no citations was rated `medium` precisely because there was nothing to cite. Density now measures the share of contested assertions that cite text.

**Bug found and fixed in this pass:** `priority_actions` was empty because the service filtered for negative impacts while the engine emits points-lost as a positive magnitude. Service corrected; `API.md` clarified (impact is a positive magnitude summing to `100 − overall`).

## Phase 7 — ATS compatibility engine ✅

**Implemented:** AT-01 extraction fidelity, AT-02 reading order, AT-03 structural hazards, AT-04 date parseability, AT-05 contact parseability. The five ATS checks *are* the `ats_compatibility` category — scored once, reported once, never computed twice with two answers. The mandatory disclaimer ships inside the payload.

**Verified:** estimate 88.2 on the reference resume with 3 pass / 1 warn / 0 fail; ambiguous dates fail AT-04; a low-confidence extraction caps the estimate below 70.
